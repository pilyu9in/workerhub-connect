## Быстрый старт

1. **Скачайте** [workerhub.cmd](https://github.com/pilyu9in/workerhub-connect/releases/latest/download/workerhub.cmd) и откройте двойным щелчком. Приложение, которое хотите подключить, должно быть уже установлено.
2. **Выберите язык и приложение** стрелками ↑ ↓, подтвердите Enter. Для отмены — Esc или Ctrl+C.
3. **Вставьте API-ключ** из раздела «Обзор» в кабинете WORKERHUB и выберите модель. При вводе ключ скрыт.
4. **Полностью перезапустите приложение или терминал**, включая фоновые процессы. Можно начинать работу.

Чтобы подключить другое приложение или сменить модель, запустите файл ещё раз. Codex и Codex CLI используют общие настройки.

```text
WORKERHUB

Что подключить?
  Claude Desktop
  Claude Code CLI
> Codex
  Codex CLI
```

Один CMD-файл со встроенным PowerShell. Не нужны Node.js, npm или права администратора. Скрипт настраивает подключение, не устанавливая и не обновляя приложения.

## Что подключается

| Приложение | Что настраивает скрипт |
| --- | --- |
| **Claude Desktop** | Профиль WORKERHUB в режиме стороннего шлюза, API-ключ и список доступных моделей Claude. Выбранная модель становится первой в списке. |
| **Claude Code CLI** | Пользовательские переменные окружения Windows: адрес шлюза, API-ключ, модель по умолчанию и псевдонимы семейств Claude. |
| **Codex** | Провайдер WORKERHUB, модель по умолчанию и локальный каталог совместимых моделей в общих настройках Codex. |
| **Codex CLI** | То же подключение, что и у приложения Codex. Существующий официальный вход сохраняется. |

### Модели и стоимость

Список моделей загружается из актуального каталога WORKERHUB при каждом запуске. Для Codex он сверяется с официальными метаданными клиента. Показываются только подходящие текстовые модели; модели изображений и аудио не добавляются.

Модели **не скачиваются на компьютер**. Запросы отправляются через WORKERHUB и оплачиваются с баланса аккаунта по действующим тарифам. Скрипт не отправляет платных запросов и не проверяет ключ через генерацию: его работоспособность проверится при первом запросе приложения.

У Claude Code CLI настраиваются модель по умолчанию и доступные семейства; скрипт не добавляет ему отдельный полный каталог выбора. Для обновления списка моделей в Desktop/Codex запустите скрипт заново.

## Как это работает

| Клиент | Адрес подключения |
| --- | --- |
| Claude Desktop / Claude Code CLI | `https://workerhub.cc/worker-api` |
| Codex / Codex CLI | `https://workerhub.cc/worker-api/v1` |

Для Claude используется корневой адрес Anthropic-совместимого шлюза: клиент сам добавляет `/v1/messages`. Codex использует Responses API. Выбирать адрес вручную не нужно.

<details>
<summary><strong>Какие настройки меняются</strong></summary>

**Claude Code CLI**

В пользовательском окружении Windows сохраняются `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_MODEL`, псевдонимы `ANTHROPIC_DEFAULT_*_MODEL`, настройки вспомогательной модели. `ANTHROPIC_API_KEY` очищается, режимы Bedrock/Vertex/Foundry отключаются, чтобы не конфликтовать с выбранным шлюзом.

**Claude Desktop**

В `%LOCALAPPDATA%\Claude\claude_desktop_config.json` и `%LOCALAPPDATA%\Claude-3p\claude_desktop_config.json` включается `deploymentMode = "3p"`. В `%LOCALAPPDATA%\Claude-3p\configLibrary` добавляется и активируется отдельный профиль WORKERHUB. Остальные профили сохраняются.

**Codex / Codex CLI**

В `%USERPROFILE%\.codex\config.toml` обновляются выбранная модель, провайдер `model_providers.workerhub` и путь к `workerhub-models.json`. Если задан `CODEX_HOME`, используется он. Ключ сохраняется в пользовательской переменной `WORKERHUB_API_KEY`. Файл `auth.json` не изменяется.

Ключ хранится локально в переменных окружения или профиле приложения **без дополнительного шифрования**. Не публикуйте эти настройки и резервные копии с ключом.

</details>

<details>
<summary><strong>Резервные копии и возврат настроек</strong></summary>

Перед изменением существующего файла создаётся точная копия рядом с ним: `имя-файла.workerhub-ДАТА-ID.bak`. При ошибке записи скрипт пытается откатить изменения текущего запуска. Одновременное изменение файла другой программой прерывает настройку.

Для ручного возврата закройте приложение и восстановите нужную соседнюю `.bak`-копию. Настройки новых файлов, у которых не было предыдущей версии, нужно удалить вручную, если они больше не нужны.

Переменные окружения не имеют файловых `.bak`-копий: автоматический откат действует при ошибке текущего запуска. Чтобы сменить провайдера позже, верните прежние значения через пользовательские переменные Windows или инструмент настройки провайдера. Для Claude Desktop можно также выбрать прежний профиль. Для Codex восстановите прежний `config.toml` и уберите `WORKERHUB_API_KEY`, если она больше не нужна.

</details>

## Если что-то не получилось

| Ситуация | Что сделать |
| --- | --- |
| Приложение использует старое подключение | Полностью закройте его, включая фоновые процессы, и откройте снова. Для CLI откройте новый терминал; при запуске из IDE перезапустите и её. Локальные переопределения клиента могут иметь приоритет над пользовательским окружением. |
| Ошибка загрузки каталога | Проверьте доступ к WORKERHUB и GitHub, затем повторите запуск. До загрузки каталога настройки не записываются. |
| Ошибка ключа или баланса в приложении | Проверьте активность ключа и баланс в кабинете. Вставляйте сам ключ, без `Bearer` и пробелов. |
| В Codex Desktop не видны модели | Перезапустите приложение. В некоторых версиях список зависит от официального входа в Codex; существующий вход скрипт сохраняет. При необходимости проверьте подключение через Codex CLI. |
| Скрипт отказался менять `config.toml` | Обычные секции, включая пути и плагины в кавычках, поддерживаются. Многострочные строки и некоторые inline/dotted определения провайдеров намеренно отклоняются. Используйте отдельный `CODEX_HOME` или настройте провайдера вручную. |
| Файл открывается в редакторе | Сохраните именно `workerhub.cmd`, не HTML-страницу и не `.txt`. Запускайте в интерактивном окне Windows. |

## Для разработчиков

Весь исполняемый код находится в [workerhub.cmd](workerhub.cmd). CMD-часть запускает встроенный PowerShell с режимом выполнения только для этого процесса. Системная политика выполнения не меняется.

Файл должен оставаться в UTF-8 **без BOM** с окончаниями строк **CRLF**; это закреплено в `.gitattributes`. Проверки Windows PowerShell 5.1, редактирования TOML и сохранения посторонних настроек выполняются в GitHub Actions без реального ключа и запросов генерации.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/smoke.ps1
```

Нашли ошибку? [Создайте issue](https://github.com/pilyu9in/workerhub-connect/issues), указав приложение и текст ошибки. Удалите API-ключи из логов и конфигурации перед отправкой.
